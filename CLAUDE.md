# Hola · 光辉联合 — notes for Claude Code

Hola puts several AIs (Claude, Codex, Gemini, plus any OpenAI-compatible API or CLI) into one group chat on the user's own Windows PC. The user is the "boss" (包工头); the AIs are equal teammates.

## Product principles (from the owner — don't break these)
- No @ → every participating teammate answers **at the same time, independently** (they can't see each other's answer that round).
- Order only comes from the boss's @ sequence (`@Gemini … @Claude …` runs in that order).
- Teammates decide for themselves whether a question is worth discussing, debate over rounds (each declares agree / object), reach consensus, and one writes a **team conclusion**. This judging-and-concluding process is the core value of the product.
- Consensus → the team acts on its own (hand-offs run). No consensus within the round limit → the boss decides: execution waits until they pick an option or reply.
- Teammates are equals; no AI is the permanent foreman.
- The boss shouldn't see backend noise: running teammates show playful status labels (打螺丝中, 去厕所了…); raw steps only when Settings → "显示后台过程" is on.
- Delete means delete (conversation folder removed for real).
- Everything is bilingual (中文 / English), switchable in Settings.

## Layout
- `server.js` — entry point only (`require('./lib/http')`). The backend lives in `lib/`, zero dependencies (Node 18+), CommonJS, **each module may only require modules below it** (checked by `static.test.js`):
  `core` (paths, config, settings, `T()`, profile, `broadcast`, `fileExists`) → `members` (members, access / model / effort args, resolve / spawn / check CLIs) → `convs` (conversations, projects, files, Office text versions, media capture, `safeJoin`, `activeIds`) → `library` (图片库 / 文件库: uploads in workspace/资料库 + a live view of every conversation attachment and output; `attachFromLibrary` copies into a conversation via `finishAttachment`, the same path as uploads) → `browser` (built-in browser for teammates: `setBackend` from the desktop shell, per-run passes, approvals, one-driver lock, `withBrowser` adds the MCP config to Claude's args) → `run` (output parsers, CLI runner, OpenAI-compatible API runner) → `skills` (skill library) → `prompts` (agent prompts, phase guides, tags) → `engine` (mentions, `pump`, discussion → conclusion → decision, hand-offs, memory, skill distillation, `agentTurn`, `stopConv`) → `build-check` (release signature) → `http` (routes, static files, startup). `ROOT` in `core` is the code folder (`lib/..`). Inside a module, sections keep their `// ------` banners. Don't reassign exported `let`s after load (importers keep the old value); mutate in place (see `ORDER`).
- `office.js` — zero-dependency zip/XML reader: docx/xlsx/pptx → Markdown text versions and HTML previews. Exports `readZip` too.
- `public/index.html` — page structure only; styles in `public/app.css`, script in `public/app.js` (one classic script, global functions; keep it that way unless boot code is moved last). All page files are served `no-store` and must be on the static whitelist in `lib/http.js`. Layout is sidebar | `#sideGrip` | main | `#splitGrip` | `#split` (file preview pane, replaces the old preview dialog). Sidebar width, collapse (`body.side-off`), chat width (`body[data-width]` normal / wide / full) and split width live in localStorage. Markdown links that point into the current conversation folder (absolute, `file:///`, `<…>` or relative) become `a.flink` and open in the split pane. `public/i18n.js` — Chinese→English dictionary `D` + regex patterns `P`; translates the DOM via MutationObserver. Anything marked `data-raw` (AI text, titles, file names) is never translated.
- `demo/` — `node server.js --demo` uses `demo/config.json` and `demo/fake-ai.js` (scripted teammates, no accounts). Data goes to `data-demo/` and `demo-workspace/`.
- `config.json` — member definitions (commands, args, parser). The repo copy is the **safe default** (Gemini read-only, no dangerous flags).
- Windows launchers: `Hola.vbs` (UTF-16 LE with BOM; starts server hidden, opens Edge/Chrome `--app=`), `SETUP.bat`, `START.bat`, `START-DEMO.bat`, `Create-Desktop-Icon.bat`, `Login-Claude/Codex/Gemini.bat`, `tools/install-shortcut.ps1`. All `.bat` files must stay CRLF + UTF-8 (`chcp 65001`), messages bilingual.
- **Desktop app (Electron)** in `desktop/`: `main.js` picks a free port, sets `HOLA_DATA_DIR` (system app-data `data/`) and `HOLA_WORKSPACE` (Documents\Hola) — overridable by `location.json` in app-data (`dataDir`, `workspace`, `config`) — then `require`s the program's `server.js` in-process and opens a window. `updater.js` = automatic updates of the **program only** (server, lib, public…): GitHub `releases/latest` → asset `hola-app-x.y.z.zip` → signature + every hash checked with the key in the shell's own `tools/release-files.js` → extracted to app-data `app/<version>/`, `current.json` pointer (`version`, `prev`, `bad`, `lastStart`). A version that throws or never answers `/api/ping` is marked bad and Hola falls back to the previous good version. Shell updates only open the download page (the installer can't be signed: CI builds it, the key never leaves the author's PC). `npm install` is dev-only (electron, electron-builder, playwright-core); the program itself stays zero-dependency. `package.json` `build` = electron-builder config (`asar: false`, NSIS one-click, Mac arm64 + x64 DMGs ad-hoc signed by `build/after-pack.js`, icon `build/icon.png` from `tools/make-icon.js`). Test switches (`HOLA_USER_DATA`, `HOLA_TEST_HIDDEN`, `HOLA_UPDATE_URL`, `HOLA_UPDATE_DELAY_MS`; `HOLA_UPDATE_PUBKEY` and `HOLA_BROWSER_ALLOW` only when not packaged).
- **Title bar and built-in browser (shell 1.1+)**: frameless window (`titleBarStyle: 'hidden'` + `titleBarOverlay` on Windows, `hiddenInset` on Mac); `desktop/preload.js` exposes `window.holaDesktop` (`setTitleBarColors`, `browser.*`) — the page checks for it, so the web / zip version just lacks these features. `desktop/browser.js` owns one `WebContentsView` (partition `persist:hola-browser`, all permissions denied, `webRequest` blocks loopback / `file:`, Electron stripped from the UA) and exposes only primitives (`navigate`, `exec`, `click`, `insertText`, `pressEnter`, `capture`, `state`, `reveal`, `setBounds`; interface `v: 1`). `main.js` hands it to the server with `require(path.join(code.dir, 'lib', 'browser.js')).setBackend(...)` (same module instance as the server, even after a program update) and only accepts browser IPC from the main window. The page sends the `#spWeb` rectangle; the native view paints over HTML, so `syncWeb()` hides it while a dialog or the lightbox is open. Teammate tools: `lib/browser.js` builds read / click / type logic as in-page scripts (element numbers in `data-hola-ref`); `desktop/browser-mcp.js` is a dependency-free MCP stdio server run as `process.execPath` + `ELECTRON_RUN_AS_NODE=1`, forwarding to `POST /api/browser/tool` with a per-run token. Claude only (`--mcp-config <file in .hola>` appended last; `mcp__hola-browser` added to `--allowedTools` in safe mode; `MCP_TOOL_TIMEOUT` raised). Clicks and typing wait for the boss (`.bask` cards → `/api/browser/answer`; 3-minute timeout = no; `settings.browserAsk` turns it off; "allow for this chat" lasts until restart). Token revoked when the run ends or the boss stops the conversation. Codex / agy not wired yet (Codex would need TOML `-c mcp_servers…` through cmd.exe).
- Data guard: `lib/http.js` writes `hola.lock` (pid, port) in the data folder and refuses to start (exit 3, `ANOTHER_INSTANCE`) if a Hola on that port answers `/api/ping` with the same `data` folder; the desktop shell checks first and shows a dialog.
- Release CI: `.github/workflows/release.yml` on tag `v*`: Windows job checks tag = `package.json` = `release.json` version, runs all tests with `HOLA_RELEASE_CHECK=1 HOLA_REQUIRE_APP=1`, builds the installer and `node tools/pack-app.js` bundle, re-tests them (`HOLA_APP_EXE`, `HOLA_BUNDLE_DIR`); Mac job (continue-on-error, beta) tests and builds DMGs; release job publishes with `SHA256SUMS.txt`.
- Mac launchers (beta, not yet run on a real Mac) live in `mac/`: `common.sh` (finds the Hola folder, extends PATH), `SETUP.command` (installs Claude Code / Codex with `npm -g --prefix ~/.hola-tools`, agy via its `install.sh`, logs in, clears quarantine, chmods), `make-app.sh` (generates `~/Applications/Hola.app` + desktop link), `START.command`, `START-DEMO.command`, `Login-*.command`. They must stay LF, no BOM, executable (`git add --chmod=+x`), and bash 3.2 / BSD-tool compatible. `server.js` only differs on non-Windows in PATH setup, `resolveCmd`, process-group kill (`detached` + `kill(-pid)`) and the login-script names in `loginHint`.
- Licence: PolyForm Internal Use 1.0.0 since 2026-10 (free use and modification for individuals and companies; no redistribution). `LICENSE` is the official text verbatim plus a `Required Notice:` line; don't paraphrase it. Earlier releases stay Apache 2.0.
- Official-build check: `release.json` = SHA-256 of the program files (list and hashing in `tools/release-files.js`; text files hashed with BOM stripped and CRLF→LF so git line-ending conversion doesn't trip it) + an Ed25519 signature made by `tools/release-sign.js <version>` with the author's private key (`.release/`, gitignored, never uploaded). `checkBuild()` in server.js verifies against the embedded `RELEASE_PUBKEY` and sends `build: {status: official | modified | unofficial | dev}` in `init`; the sidebar badge (`#buildTag`) shows it. A `.hola-dev` file (gitignored) marks the author's own copies as 开发版. **Re-sign after any change to a listed file, right before publishing**, or official users will see 非官方版.
- `GUIDE.html` (bilingual user guide with a 中文/English switch), `README.md` (Chinese) and `README.en.md` (English) — keep all three in sync when features change.

## Runtime data (gitignored)
- `data/`: `settings.json`, `profile.json`, avatar, `members.json` (custom members incl. API keys), `projects.json`, `skills/<id>/SKILL.md` (+ `.history/`), `skills-meta.json`, `hola.log`.
- `workspace/<conv-id>/`: one folder per conversation — `.hola/chat.json`, `.hola/聊天记录.md`, `.hola/memory-history/`, `.hola/skills/` (enabled skills mirrored before each CLI run), `对话记忆.md`, `附件/`, `产出/`, `文字版/`, plus whatever teammates produce.

## How the engine works
- Members are spawned per turn: `claude -p --output-format stream-json …` (parser `claude-stream`), `codex exec --json … -o {OUTFILE} -` (`codex-json`), Gemini via Antigravity CLI `agy -p {PROMPT} --output-format json` (`agy-json`; Gemini CLI no longer serves personal subscriptions), or OpenAI-compatible streaming APIs. Placeholders in args: `{PROMPT}`, `{ROOT}`, `{OUTFILE}`, `{WORKSPACE}`.
- Permissions: for the `claude-stream` / `codex-json` / `agy-json` parsers, Teammates → Edit has a "完全权限" (full access) switch saved as `settings.memberPrefs[id].access` (`full` / `safe`). `withAccess()` rewrites the args from `config.json` (adds `--dangerously-skip-permissions` / `--dangerously-bypass-approvals-and-sandbox`, or the safe flags) and sets `readOnly`; with no saved choice, `accessOf()` reads the level from the args as written.
- Models: same three parsers get a model dropdown (`settings.memberPrefs[id].model`, validated by `MODEL_RE` because it goes on a command line that may pass through cmd.exe). `withModel()` runs after `withAccess()`. Thinking effort works the same way (`memberPrefs[id].effort`, whitelist `EFFORTS`, `withEffort()`: `--effort` for Claude/agy, `-c model_reasoning_effort=` for Codex, whose levels vary per model). Lists come from `modelChoices()`: Claude aliases, Codex `models_cache.json` (visibility `list`), `agy models` (cached 10 min). The model actually used is stored on each message (`msg.model`).
- Usage: parsers normalise to `msg.usage = { input (incl. cache), cached, output }` (Claude adds cache read/creation to `input_tokens`; Codex from `turn.completed`; agy from its JSON; APIs via `stream_options.include_usage`). The UI shows it per message and per-teammate totals in the status popover. Don't show Claude's `total_cost_usd`: subscribers would read it as a charge.
- Per-conversation job queue (`pump`): job types `turn`, `discuss`, `skill`. `runDiscussion` = parallel initial round (tag `【需要讨论】是/否`) → discussion rounds (tag `【立场】同意/有异议`) until all agree or `maxDiscussRounds` → conclusion by `settings.conclusionBy`. Without consensus the conclusion lists `【方案A】…` lines (parsed into `msg.options`), gets `awaitDecision`, and no hand-offs are queued; the boss answers via `/api/decide` (option buttons) or any non-@ message (`pendingDecision`), which queues a `decided` turn for the writer, whose @s then hand off as usual. Demo: a question containing 分歧/拍板 (or split/disagree) runs the no-consensus script. Hand-offs happen when a reply @s a teammate (capped by `maxAutoTurns`). After a round, `updateMemory` asks the keeper for `【本次变化】` + `<<<记忆 … 记忆>>>`.
- `agentPrompt()` assembles: roster, rules, boss profile, project context (`projectText`: brief + sibling tasks' decisions from their memory), skill index (`skillsPromptText`), conversation memory, file listing, transcript, phase guide. Teammates mark skill use with a first line `【技能】名字`.
- Skills: SKILL.md with `name` / `description` front matter (Claude Skills compatible). "存为技能" queues a `skill` job that distills the conversation into `<<<技能 … 技能>>>`; same name = merge into new version.
- SSE `/api/events` pushes `init`, `convs`, `state`, `msg`, `proc`, `memory`, `members`, `settings`, `profile`, `skills`, `projects`. All POST `/api/*` need header `X-Hola: 1` and a localhost Origin. Server listens on 127.0.0.1 only (3456; demo 3457).

## Conventions
- User-facing server strings go through `T('中文', 'English')`. Prompts to the AIs are Chinese (the reply language is set by `replyLangRule()`).
- New UI strings: write them in Chinese in `index.html`, then add the English to `D` (or a regex to `P`) in `public/i18n.js`. Wrap dynamic AI/user content in `data-raw`.
- Windows quirks already handled — don't regress: manual PATH scan in `resolveCmd` (where.exe garbles Chinese paths), `.cmd` shims spawned via shell with quoting, `taskkill /T`, GBK fallback in `decodeOut`, `cleanEnv()` strips `ANTHROPIC_API_KEY` so Claude uses the subscription.
- Keep it zero-dependency. No build step.

## Testing
- **Automated: `node --test "tests/*.test.js"`** (~8 s, zero dependencies). Run it after every change and before every upload. Each test file starts its own throwaway Hola in demo mode (`HOLA_DATA_DIR` / `HOLA_WORKSPACE` point at a temp folder, `HOLA_DEMO_FAST=1` makes fake teammates answer instantly) and drives it over HTTP like the UI does:
  - `flow.test.js`: discussion, consensus, hand-off, memory, split → decide (button and typed), @ order, stop, skills, projects, rename, delete, attachments / Office / preview, request security. `HOLA_TEST_DISOBEY=1` makes the fake conclusion @ someone while split, to prove the server blocks it.
  - `members.test.js`: `tests/fixtures/fake-cli.js` replays the real output formats of Claude stream-json, Codex JSON and agy JSON; checks parsing, usage normalisation, model / effort / access flags on the command line, a local fake OpenAI-compatible server for API teammates. `CODEX_HOME` points at `tests/fixtures/codex-home`.
  - `static.test.js`: syntax, line endings / BOM / encodings of launchers, bash 3.2 compatibility, licence text, safe default config, .gitignore.
  - `update.test.js`: updater with a throwaway key pair — tampered / unsigned / re-signed manifests, unlisted files, path escapes, downgrades, `minShell`, crash rollback to the previous good version, offline. `HOLA_BUNDLE_DIR=dist` also installs the real signed bundle.
  - `app.test.js` / `app-update.test.js` (need `npm install` + `node node_modules/electron/install.js`; skipped otherwise): drive the real Electron app with playwright-core — chat, decision card, split preview, layout, English leftover scan, no console errors; and a full update cycle against a local fake GitHub. `HOLA_APP_EXE` points at a packaged `Hola.exe`.
  - `build.test.js`: official badge on a simulated download (CRLF conversion, modified file, tampered / missing release.json, .hola-dev). Set `HOLA_RELEASE_CHECK=1` to require "official" (release gate: forgot to re-sign = fail).
- Black-box on purpose: the tests only use HTTP and files, so they survive refactoring.
- `node -c server.js && node -c public/i18n.js` for a quick syntax check.
- `node server.js --demo`, open http://localhost:3457, run a question with no @ (parallel → discussion → conclusion → hand-off → memory), click 存为技能, create a project and two tasks. Set `HOLA_DEMO_DUMP=1` to make fake teammates write their received prompt to `.hola/prompt-<Name>.txt`.
- Check both languages (Settings → 界面语言 / Language). Playwright with Chromium works well for screenshots.
- To stop the demo server without killing your own shell: `kill $(pgrep -f "^node server.js")` (on Windows, close the window or use Settings → Quit Hola).
